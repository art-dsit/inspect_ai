WALK COMPLETE

You have been round the whole system once.

The method the review uses — reusable on any surface you meet next:
  1. Name the attacker-controlled data. Model output, request bodies, filenames, archive bytes, stdout.
  2. Find the component that acts on it, and ask what authority that component holds — host filesystem? provider credentials? the score?
  3. Keep the labels straight. Some surfaces are observed in the code, some conditional on configuration, some only possible until someone tests them, some by design — a grant the evaluator made on purpose — and some already have an existing control. Never quietly promote one to the next.

Parts of the tree the walk skipped, and where to go next: the rest of _eval/ and the task runner (retries, epochs, sample concurrency, what happens when a sample errors), the log recorders under log/_recorders/, what samples sharing a host can do to each other, and the sidecars that drive a browser or a desktop for the agent. Each one answers to the same two questions you have been asking all the way round: whose data is this, and what authority is acting on it?
